# ChatGPT X UI kit and component gallery

Native UIKit reproduction of the approved iOS 6 design prototype
(`design/uxui/`, commit 85db75d) as reusable components, plus a separate
gallery to develop and review them in isolation. Since 10 November 2026 the
production ChatGPT X screens are assembled from the kit (build 43); see
`docs/kit-app-20261110.md` for the app side and the device acceptance.
Rules for building and extending the kit (and the only-kit rule for app UI):
`docs/ui-kit-brief.md`.

Target: iPhone 5 / iOS 6.1.4, SDK 6.1, ARMv7, MRC (`-fno-objc-arc`), Objective-C.
The kit links only UIKit, Foundation, CoreFoundation and CoreGraphics (the same
public set `scripts/build-chat.py` allows). QuartzCore headers are imported for
`CALayer` messages only; QuartzCore is not linked. No network, account,
session or send code is involved.

Optional slots: a component exposes a capability flag (e.g. `showsPlus`,
`stopAvailable`, `copyMenuEnabled`, `RCActionBar.actions`). The app sets it from
what this build and the account can really do: everything available is always
shown. The «Возможности» stage setting (10→6) was removed from the app on
12 November 2026. The gallery keeps its stage switcher only to review the
prototype's staged layouts. Slots never appear as disabled "coming soon" controls.

## Dark appearance

`[RCTheme setAppearance:RCAppearanceDark]` follows the prototype's `#app.dark`
(the "Оформление: Тёмное" setting, stage 7). It posts
`RCThemeAppearanceDidChangeNotification` and sets the iOS 6 status bar to
`UIStatusBarStyleBlackOpaque`. The answer card, action bar, composer, user
meta line, placeholder and grouped-table backgrounds and headers recolour live.

## Opening the gallery

The gallery list has a stage switcher (10…6), text-size steps and the light/dark appearance switch; each page
shows one component family in all its states. It runs entirely offline.

ChatGPTXKit (recommended for device review; separate bundle):

```bash
cd ios/ui/gallery-app && THEOS=~/theos gmake clean package messages=yes
```

Development route for screenshots without touch input:
`chatgptxkit://page/<Name>?stage=8&size=2&open=1&y=400&dark=1`, where `<Name>` is one
of Theme, Stock, Glyph, HUD, Title, Banner, Drawer, Empty, UserMessage, Answer,
Markdown, Parts, Composer, Activity. `open=1` opens the sheet, the assembled chat or a busy HUD, `open=2` also
slides the drawer out, `y` scrolls the page, `dark` picks the appearance.

Inside ChatGPT X (debug only): apply `ios/ui/integration/chat-app-gallery.patch`
to `ios/standalone/chat-app`, then build with `OR6_UI_GALLERY=1`. The app then
launches into the gallery and never creates the chat coordinator, so there is no
session or network. Without the flag nothing from `ios/ui` is compiled.
That build keeps the `io.ozio.chatgptx` bundle ID, so do not
install it over a working ChatGPT X; use ChatGPTXKit on the phone instead.

### Text rendering findings on iOS 6.1.4 (found and fixed)

- **Multi-line `UILabel`.** Plain `label.text` and `-sizeWithFont:` disagree on
  where lines break, so the boundary word was drawn clipped or truncated ("можно
  закры…", "Ответ появится … мере"). A device diagnostic showed the attributed
  variant lays out correctly. Multi-line labels now go through `RCLabelSetText`,
  and are measured with `RCMeasureText` (`boundingRectWithSize:` with the same
  attributes). Single-line labels are unaffected. Keep using these helpers.
- **₽ (U+20BD)** is not in the iOS 6 system fonts and draws as a box.
  `RCDisplayText` shows it as "руб." in answers, Markdown, bubbles, chart and task
  cards. Copy and send keep the original text.
- Stage-10 plain text now also removes `*italic*` markers and `[text](url)` link
  syntax. The prototype's `S.plain` kept them.

### Line breaks in UITextView (found and fixed)

On this iPhone (iOS 6.1.4), `UITextView -setText:` replaces every `\n` with a
space (U+0020). A device-logged matrix showed this on a bare text view, off-window and in
the window, with a zero frame, with scrolling or editing off, and after a
run-loop delay. `-setAttributedText:` keeps U+000A, and so do `UILabel` and
`UITextField`. `RCComposerView -setText:` therefore assigns an attributed string
with the field's font and colour. On the device the multi-line composer now shows
its lines at stages 10 and 8. Typed Return was not tested. The root cause inside
UIKit is not known: it may depend on how this toolchain links the app, since
stock apps keep line breaks.

The production chat app now uses `RCComposerView` (and attributed setters in its
own editor), so a restored multi-line draft keeps its lines; checked on the device
with a three-line draft.

Empty text (10 November 2026, physical ordinary78 ui37–41): after Select All +
Backspace + Done in the app's full-screen editor, the composer showed no placeholder
and kept the two-line `"\nM"` height (~52 pt instead of 32). The draft was a single
`"\n"` (length 1, device-proven): the attributed editor text view on iOS 6 reads an
empty last paragraph back with one extra `"\n"`. QA80 showed the same for a typed
Return: one Return at the end of a 167-character draft read back as ORIGINAL+`"\n\n"`
(169 instead of 168). The editor (`OR6ChatTextEditorController`) now keeps the intended
text: the original, then every edit UIKit reports
(`-textView:shouldChangeTextInRange:replacementText:`) applied to it. Done returns it
when the view reads exactly it, or it plus that one extra `"\n"` while its last
paragraph is empty. Any other read-back, such as a change UIKit did not report, is
returned as read: typed and original line breaks are kept, and nothing is trimmed or
normalised. Select All + Backspace + Done passed on the device (QA80). In QA81 the
Return correction returned the right 168 characters, and the API7 binding and the
owner-change guard below passed.

QA81 then showed the same mechanism the other way round: an assigned attributed `"\n"`
only ends a paragraph. Setting ORIGINAL+`"\n"` (168) in the composer left one paragraph,
which reads back as the 167-character original. The composer's own change notification
then copied that read-back into the chat state. The model now lives in the kit
(`RCComposerView.h`): `RCTextViewStoredText` (assign one more `"\n"` when the last
paragraph is empty), `RCTextViewIntendedText` and `RCTextViewEditedText`.
- `RCComposerView` keeps the intended text from `-setText:` and from every reported
  edit. `-text`, the placeholder, `hasContent` and the field height all use it.
- A change notification sent while `-setText:` assigns is not passed to the delegate as
  a user edit.
- The app's editor uses the same three functions, and opens a draft whose last
  paragraph is empty in the stored form.
- `+[RCComposerView lineBreakProbe]` is a QA-only device check: it sends synthetic texts
  through a bare text view and a real composer. Per case it reports lengths, SHA-256 and
  whether the intended text is recovered. No user text is involved.

The stored form (`"a\n"` assigned as `"a\n\n"`) is inferred from the three device
observations, not yet observed directly. The probe and the QA82 replay confirm or refute it.

Opening the editor no longer needs a reserved draft. On the stage 7 path, the
`composer.editor.*` binding uses the chat's own draft ID (`chat7DraftRequest`). That is
local state in API7G, so editing never runs `messages.newDraft`, which checks models
over the network. The binding also drops Done when the field's text changed while the
editor was open. When `composer.editor.*` is not granted, the fallback editor applies
Done only into the context it opened in: screen epoch (background, owner/credential
change and teardown bump it), Core generation, chat, draft and field text.

An empty draft opens through the plain setter. As a guard, `RCComposerView -setText:`
also assigns an empty value with the plain `-setText:@""` and re-applies font and
colour, because an emptied `UITextView` may return `nil` from `-font`. The field is
measured with `RCTextViewFont(_tv.font)`. Offline: `tests/chat-keyboard/verify.py`;
the device replay is separate.

configuration calls `-showPreviewIn:file:message:conversation:`: a cached thumbnail is shown at

so not while the list is dragged) drops settled parts and parts that left their window (after a
2 s grace), then starts at most one image that is on screen now (intersects the window), newest
part first, through the same `-showFile:…` path as a tap: one `assets.download` for the exact
conversation/message/file, or for a cached asset only `assets.status` + the local bytes. The
next queued image starts when that one settles (the preview change re-renders its row and pumps
the queue); parts in the window but off screen are probed again every 0.5 s (geometry only). A
re-render or cell reuse of the same image replaces its probe (one entry); an image already
loading on another screen of the same Core is watched, not repeated. Failed, unknown and
unavailable images are never queued; a start refused at pump time is left to an explicit tap.
Background, owner change and teardown (`-invalidate`) empty the queue. The bytes come from the
coordinator's trusted in-process resolver (`OR6Chat7SetImagePreviewResolver` →
`-[OR6API7AllComposition imagePreviewDataForAsset:]`) and a bounded ImageIO thumbnail (≤720 px,
PNG/JPEG, ≤8 MB / 24 Mpx header check) decoded off the main thread; six thumbnails stay in memory
and an evicted one is decoded again from its revalidated asset, never downloaded again. Сохранить /

first. A download is a read: one cancelled by background, owner change or teardown
(`-invalidate`) is offered again and the next display fetches it (still bounded by the
automatic-start limit); a possibly-sent failure shows Failed, which only an explicit tap retries.

lock during a download left the image Unknown for the whole app session). Background, owner change
and teardown still drop late replies and decodes.
A context change under the request (`stale_context`, e.g. the session rebinding at launch) is
retried automatically after 1.5 s. `assets.download` (`OR6API8Media`) reuses an intact local copy
of the same file instead of downloading it again. Downloads, Library images and read-aloud audio
are vault cache assets (`-[OR6Files importCacheURL:]`): identical bytes are stored once, and when
an import needs room in the 256 MiB / 256-asset vault (or the device would keep under 100 MiB

ordinary assets are never evicted. Before this, the 24 MiB / 32-asset vault filled with repeated
downloads, and every new image failed with `storage_failure` (12 November 2026).

journal-recorded downloads become cache assets, and byte-identical duplicates are removed. The
copy named by the preview record is kept. On the phone this took the vault from 27 assets /

### Read-aloud mini player (12 November 2026, graphite redesign)

`RCReadAloudBar` is the read-aloud strip below the navigation bar. It started as
a port of the approved `S.player` (`design/uxui/js/s-sheets.js`, jade strip) and
was redesigned at the user's request as graphite glass in the iOS 6
media-control idiom, so it reads as a player rather than a jade notice banner:

- Glass: a four-stop graphite gradient with a mid-height sheen break, a light top
  highlight, a dark bottom stroke and a 3pt drop shadow over the content below.
  Colours are named in `RCTheme` (`readAloudTop/Bottom/Ink/SecondaryInk/
  FailureInk/Stroke/Groove/FillColor`). Dark appearance is deeper graphite.
- Left: a convex round 34pt knob in a 44pt target (concave when pressed) with
  an engraved white play/pause glyph. It shows a white spinner while preparing
  and the `regen` glyph to retry after a failure.
- Middle: the bold state title with a three-bar level meter, which bounces while
  playing and rests when paused; elapsed/total time; and a 4pt progress groove
  whose fill moves smoothly across the one-second status ticks. A failure
  hides the time and groove and wraps the salmon failure text.
- Right: speed and Close in the new `RCButtonStylePillDark` capsule (26pt, hit
  areas 44pt tall). Close carries a drawn engraved ×.
- Presentation: `-setPresented:animated:` slides the strip down from under the
  navigation bar and back up, over `+presentationDuration` (0.3s). A host gives
  it `presented ? heightForWidth: : 0` and animates its own layout in step. The
  chat does this, so messages move with the strip. A dismissed strip is hidden
  from VoiceOver and touch.

The height is 44pt at normal text size, growing with text size or wrapped
failure text. Height-change callbacks are sent only when the height actually
changes, not for each time tick. The level meter uses UIView animations only:
the kit still links no QuartzCore.

Background playback: the app declares `UIBackgroundModes` `audio`. Around its
own resign-active teardown, the coordinator holds playback
(`OR6API7GDevice -setHoldsPlayback:`, `OR6Chat20SetPlaybackHold`). A playing or
paused read-aloud keeps its player, vault asset and strip. When the same
identity and context key are bound again, the selected20 provider resumes them,
and the strip re-reads the status. Logout, an account or context change,
switching conversations, Close and teardown still stop playback. While a player
exists, the device publishes lock-screen Now Playing details. Headset or
lock-screen play/pause reaches it through the app delegate (`UIResponder`) and
`OR6API7GRemoteControlNotification`. A status read that fails before the
session is bound again keeps the last state instead of showing a failure.

Gallery: Player/questions/link (`chatgptxkit://page/Priority7`) starts with mini

- **Аккаунт › Чат › Боковое меню** (`chat.session.drawer`, value «N из M»)
  opens a form in the style of the prototype's «Ответы» screen. It has one group,
  «Показывать в меню», with a Switch row and its drawer tile for each destination
  this account can open (`chat.settings.drawer.<key>`). The footer says that a
  hidden section keeps its content. «Новый чат» and the chat list always stay.
  Shown by default: Библиотека, Проекты, GPT, Изображения. Hidden by default,
  turned on here: Архив, Задачи, Закрытые чаты, Codex. The choice is local to the
  iPhone (`NSUserDefaults` `OR6ChatDrawerVisibility`, explicit values only).
  The drawer is redrawn as soon as a switch changes.
- **Codex home** follows `s-codex.js`. One Value row shows the computer or cloud
  (devices/cloud tile, lamp, «Подключено / Не подключено», or «Компьютер не
  выбран · Выберите компьютер или облако») and opens Connections. Below it are
  «Подключить / Отключить», or «Добавить компьютер…» when nothing is selected.
  An explanatory footer is shown while not connected. «Проверка устройства» was
  removed because secure setup is impossible on iOS 6. «Восстановление» appears
  only for an unconfirmed operation.
